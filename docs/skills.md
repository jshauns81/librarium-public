# Skill routing

Read the installed `SKILL.md` before applying a skill. Resolve its actual location
and version through the current client's catalog and private environment context.
Do not commit host-local paths, plugin manifests or authentication details.

| Work | Skills and checks |
|---|---|
| Shared context and navigation | unified-memory, graphify; provenance and inspected saves |
| Documentation | docs-governance, verification-loop; links, privacy and diff review |
| Python behavior | python-patterns, python-testing, tdd-workflow |
| APIs, input and sensitive boundaries | api-design, security-review |
| Schema and releases | database-migrations, docker-patterns, deployment-patterns |
| UI, copy and accessibility | Anti Slop core and relevant modules; current Impeccable playbook; UX standards |
| Final verification | verification-loop; actual applicable checks |

Keep optional tool choices in local configuration.
A catalog entry does not prove that a skill is installed or a service authenticated.
Use active harness tools for delegation and browser/device work.

## Complete Anti Slop and Impeccable suites

Use the relevant design and copy checks during interface work.
Load core plus only the relevant UI, copywriting, human, mobile or code module.
Use the verified current Impeccable suite, including its router and task playbook;
resolve version differences privately instead of silently using an older alias.
For UI work, [UX standards](ux-standards.md) owns hierarchy and acceptance.
Verify rendered behavior and accessibility; docs alone do not pass UI gates.

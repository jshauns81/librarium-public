## Reuse and scope

Checked the retained BL Catalog author/identity/reference contracts, Library Finish
changeover priorities and the native inspection-to-delivery pipeline. Reuse native
Library capture, catalogue comparison, independent assessment, correction generation,
EPUBCheck, preservation, delivery approval and recovery. New code supplies bounded
lineage projection and navigation/selection continuity around those existing engines.
No dependency, bibliographic resolver, repair engine or writer is added.

One preserved source owns the book header, condition, reference evidence, explicit
choices, generated copies, validation, delivery and source history. Stored origin
is historical context. Matching metadata or inventory does not grant authentication,
semantic clearance or writer authority.

## Verification scope

Behavior tests must reject foreign or malformed selections, bind output and delivery
relations, retain historical reads without mounted sources and preserve current
authentication. Mounted component tests must cover route reload/source switching,
Library/Reviews resume, reference returns and cancellation by newer input.
Synthetic browser proof must use the built app, real backend, separate worker and
generated fixtures through correction, actual output checks and held delivery.

Physical device reading, screen-reader audio and installed-beta acceptance remain
separate from source tests and Chromium emulation. No activation or real-library
operation is part of this block.

## Review regressions

Independent review found and corrected dependent-selection and recovery defects:
exact followup IDs must clear when leaving a delivery or creating a new request;
terminal recovery requests need their own historical display, separate from current
delivery state. Recorded Library identity follows the existing bounded opaque-ID
contract rather than introducing a UUID-only restriction.

Return restoration waits for the selected Resume/reference control and preserves
the source-history page. Newer input cancels deferred restoration. Before generation, choosing a new
assessment clears downstream selected results; source validation stays independent.
For an existing copy, assessment review and later delivery selection remain separate
from captured generation evidence. Same-source draft controls stay visible and
mounted during verification; only confirmed selections may start new work. Switching
sources removes the prior subtree. Comparison result
publication must survive its own durable route update.

## Open-copy assessment compatibility

An open copy admits assessment selections only for its captured catalogue work,
snapshot version and hash. Source-wide assessment history labels incompatible
rows and makes them unavailable for that copy. Starting a check against a
different reference offers an explicit return to the preserved source; it does
not publish a selection the server will always refuse. Recovery also checks the
recorded reference before publishing a reviewed assessment. The backend's strict
refusal remains unchanged, and matching queued assessments retain their durable
reload and cancellation path.
An incompatible saved request remains available for status recovery, while its
retry control is disabled with the same explanation rather than ignoring a click.

Four failing-first component regressions cover work, version and hash mismatch
and the explicit source-review path without a submission. The browser harness's
`--assessment-reference` mode uses a retained copy and a cancelled, result-free
alternate-reference fixture to check the disabled history row and matching
selection against the real backend. It never fabricates a successful assessment.

## Running the browser proof

No workflow runs this proof yet. The
[2026-11-07 suite review](research/orphaned-acceptance-suites-2026-11-07.md)
keeps it for a nightly tier after repair. On current main it fails at theme
selection, because the shipped themes are now Light/Dark behind Settings. Past
that, it fails at the replaced "Source history and recovery" disclosure. Until
the repair lands, run it by hand only on disposable synthetic state, never
against a live library or service.

Prerequisites:

- the frontend built with `npm --prefix frontend run build`;
- an isolated PostgreSQL;
- `LIBARCHIVE`, `LIBRARIUM_EPUBCHECK_DIR` and `LIBRARIUM_JAVA` set as in
  [development](development.md);
- Landlock ABI 3 or later;
- a Chrome or Chromium binary, selected with `LIBRARIUM_BROWSER`.

Each web origin loads its settings from the fixture's environment JSON:
`environment.json` for the main and truth origins, `environment-no-inputs.json`
for the catalogue origin.

```sh
uv run python .github/scripts/unified_workspace_acceptance.py prepare "$PROOF_ROOT/fixture"
echo current > "$PROOF_ROOT/truth-mode"
# Main origin, PGDATABASE=librarium_workspace_ui, 127.0.0.1:8141, with
# manage.py inspection_worker and manage.py delivery_worker on the same database.
# Serve it through a WSGI wrapper that maps "Basic reviewer:<secret>" to
# REMOTE_USER, as the web role in delivery_arm_acceptance.py does.
uv run python .github/scripts/unified_workspace_acceptance.py truth-server "$PROOF_ROOT/fixture" --port 8142
# Truth origin, separate database, 127.0.0.1:8143, LIBRARIUM_LIBRARY_URL=http://127.0.0.1:8142
# Catalogue-only origin, separate database, 127.0.0.1:8144
uv run python .github/scripts/unified_workspace_acceptance.py seed "$PROOF_ROOT/fixture" --base http://127.0.0.1:8141
node .github/scripts/unified_workspace_browser.mjs --root="$PROOF_ROOT" \
  --worker="$INSPECTION_WORKER_PID" --reviewer="$REVIEWER_SECRET_FILE" \
  --truth=http://127.0.0.1:8143 --catalogue=http://127.0.0.1:8144
uv run python .github/scripts/unified_workspace_acceptance.py check "$PROOF_ROOT/fixture" \
  --base http://127.0.0.1:8141 --browser "$PROOF_ROOT/browser/results-full.json"
```

`--journeys` skips the render matrix. `--review-return`, `--assessment-reference`
and `--captures` run the focused modes described above. The worker PID must be
the Python process itself, not its `uv` wrapper. The harness refuses to pause any
worker that is not attached to `librarium_workspace_ui`.

## Evidence and completion rules

- `S` means source behavior was inspected. It is not a click result.
- `U:<family>` identifies an existing unit assertion family below. Those tests are evidence locators, not a fresh passing run and not proof that each row is individually covered.
- `I:A` / `I:C` are initial installed-baseline observations. `C mock transport` uses the actual built App with isolated controlled HTTP; `B` names isolated built-app/worker or contract-fixture receipts; `R` names independently bound built-app fixture checks, with controlled read faults identified separately. `U interaction` identifies an inspected test-body activation from the fresh passing frontend suite. These evidence types are separate. `R:GAP` identifies an exact declaration with no supplied activation/read receipt; other unobserved variants remain explicit limits even when a declaration has evidence.
- `Gate` records exact JSX render conditions, disabled/ARIA-disabled predicates, state bindings and dynamic multiplicity. Enclosing component early returns, capability props and request guards also apply; the per-surface contracts explain them. `?yes`/`?no` mean the true/false branch of the named source condition. Absence of a disabled attribute is not proof an action is eligible.
- Source callbacks in the Result column identify the exact event/route/state transition. Named callbacks are interpreted in the per-surface contract. A native summary opens/closes its associated details. A native option selects its parent select value; it does not submit independently.
- IDs are permanent declaration IDs assigned at this baseline. Do not renumber existing IDs when controls move or new controls are added. Label branches shown in braces require separate observed results; an unchanged declaration ID groups those variants.

No production activation, library writer, file replacement, import, deletion, account change or service restart is authorized by this checklist. Use controlled synthetic data for guarded delivery and destructive outcomes. Disabled actions need their actual reason recorded; enabling them to obtain a click count is not acceptance.

## Findings and coverage limits

[The frontend findings register](frontend-findings.md) is the single triaged record. FC-001 owns the checked-copy download gap; FC-008 owns Native empty/no-match/out-of-range recovery and refresh page reset. Their implementation and current validation status belong there. The declaration ledger records behavior and evidence without creating a parallel severity register.

Initial installed assessment covered the native/global/Reviews surfaces and Catalogue/operations. The Reviews matrix exercised every shipped kind/state pair; all encountered expanded finding and record content was read, including the failure that led to the Source agreement redesign. Those observations describe the installed baseline and do not verify subsequent edits. The saved-library/synthetic supplement adds 63 declaration IDs with actual built-app browser activation under fully mocked HTTP, plus one standalone synopsis declaration first covered by component interaction and now by actual-source browser activation. It also reads all revealed words for the modeled states. Guarded delivery contract receipts are similarly marked as mocked transport; independent-worker journeys are identified separately.

All 28 formerly component-only IDs now have separate pointer/key browser activations and whole revealed-content receipts. Nineteen were exercised through the built App: ten used the isolated backend with explicitly controlled read/refusal faults, and nine used fully mocked HTTP. Nine used actual-source browser components with explicit mocked reads or callbacks because their conditional boundary is unavailable or different in the composed App. These results close the prior activation gap while retaining provider, worker and composition limits. The final Reviews retry probe preserves newer typing focus; without newer intent it focuses and announces the result summary and permits keyboard continuation. The earlier failing focus probe remains historical evidence.

The installed-review refinement has fresh bounded browser results for three new control declarations and three changed disclosure/load contracts. FINDING-003 opens an exact original raw record; FILES-035 opens structural findings; FILES-036 retries the bound structural-warning read. FINDING-001/002 retain the raw disclosure and captured-text controls with grouped presentation, and FILES-025 now shares its report cache with the warning summary. Independent browser results and the final retry-focus recheck are bound per row; earlier browser receipts remain historical for changed semantics.

No receipt set certifies every real book, all future provider values or every conditional branch. A bounded row result is not an all-state pass. Failed/unconfigured/auth-denied, stale/reconnect, long/malformed data, inactive jobs and unavailable real services retain their exact limits below. Screen-reader audio and physical-device behavior remain unverified. No installed-service job, live-library writer or account was activated for coverage.
